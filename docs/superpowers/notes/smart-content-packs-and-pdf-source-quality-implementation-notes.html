Smart Content Packs And PDF Source Quality Implementation Notes

Running notes for PDF text extraction, Markdown-ish PDF normalization, content packs, Codex pack handoff, OpenAI pack generation, and later LLM pack planning. Future worker tasks should append entries when behavior diverges from or interprets the approved spec.

Design Decisions

2026-05-27 planning

The execution plan starts with PDF source quality before content packs. Content packs become much more useful once papers and PDF-only sources can produce source-backed packet content without manual rereading.

2026-05-27 planning

PDF work stays in internal/source with a new pdf.go file. The plan avoids a separate internal/source/pdf package until there is real pressure from multiple extractor engines or broader reuse.

2026-05-27 planning

Pack planning gets its own narrow internal/pack package and a separate content-pack.json artifact. visual-packet.json remains the source-backed story spine instead of becoming a multi-output container.

2026-05-27 Task 2

The PDF extractor seam now emits real pdf_text evidence when an extractor is injected, but the package default remains unavailable until the Poppler adapter task. Missing extraction returns no placeholder item and gives Poppler install guidance.

2026-05-27 Task 3

The default PDF extractor now uses Poppler pdftotext through a package-local command runner seam. Tests fake the runner, so Poppler is not required for CI coverage. The production command uses pdftotext -layout -enc UTF-8 <path> -.

2026-05-27 Task 3

PDF normalization converts raw extractor text into Markdown-ish evidence by preserving page boundaries as <!-- page N -->, dehyphenating alphabetic line breaks, promoting common paper headings, and keeping table-like spacing intact.

2026-05-27 Task 4

Packet extraction now treats unmarked PDF lines such as Open Questions, Questions, and Research Questions as section headings. This stays narrow so broader paper heading inference remains owned by PDF normalization.

2026-05-27 Task 5

PDF extraction diagnostics are derived in the pipeline from public evidence metadata and public warnings, not from source package internals. This keeps manifest diagnostics auditable while avoiding local absolute paths and temporary PDF paths.

2026-05-27 Task 6

The first internal/pack planner is deterministic and only supports Mode: "auto". Required target content is selected from VisualPacket.RequiredText, ranked claim text, and narrow structural tokens such as title, top claims, and core message.

2026-05-27 Task 7

The pipeline now treats --pack auto as a local bundle-writing stage after visual-packet.json exists. The manifest declares content_pack and one pack_brief per deterministic target, but it still does not declare pack_image outputs because this task only writes planned briefs.

2026-05-27 Task 7 review

Generated pack directory safety now checks both pack and deterministic target directories before backup, cleanup, and brief writes. This prevents writes or cleanup from following symlinked target directories such as pack/linkedin-dense.

2026-05-27 Task 8

Codex content pack handoff remains a local prompt artifact under handoff/. When --pack auto --handoff codex is selected, the pipeline writes content-pack.json with target state handoff_ready and pack status handoff-ready, then writes handoff/content-pack-codex-prompt.md without generating target images.

2026-05-27 Task 9

Direct OpenAI pack generation reuses the existing image backend and runs only after the primary final.png succeeds. Each target updates content-pack.json to generated or failed, and the manifest declares pack_image only for target image files that exist.

2026-05-27 Task 10

The LLM pack planner uses the OpenAI Responses API with Structured Outputs and a content-pack/v1 JSON schema. Returned plans are validated against allowed target IDs, paths, states, and source-backed required content before any pack files are written.

2026-05-27 Task 10 review

Subagent review found that the initial planner slice allowed remote planning in --offline, accepted empty packs, ignored incomplete Responses API results, and pointed pack handoff next steps at the single-image prompt. The implementation now rejects --offline --planner openai, requires the full target set, rejects incomplete planner responses, and points pack handoff guidance at handoff/content-pack-codex-prompt.md.

2026-05-27 Task 11

The sample bundle is now regenerated with --pack auto and commits content-pack.json plus target briefs. Generated image files remain omitted, and the sample manifest is pruned so it does not claim the omitted local preview PNG.

Deviations

2026-05-27 planning

No approved deviation yet. The plan keeps --backend codex rejected and treats Codex image generation as a manual handoff workflow.

2026-05-27 Task 7

The planned rollback test for failed target image generation is not applicable in the current architecture because Task 7 does not generate target images. Quality validation instead rejects pack_image manifest entries for planned and handoff_ready targets; sibling target image preservation belongs with the later pack image generation task.

Tradeoffs

2026-05-27 planning

Poppler pdftotext is the stable first extractor. This gives the smoothest local experience when installed and avoids shipping native libraries, at the cost of requiring clear install guidance when Poppler is missing.

2026-05-27 planning

The first pack targets are fixed and deterministic. This gives repeatable tests and a dependable CLI contract before adding an LLM planner that can revise the same schema.

2026-05-27 subagent audit

The plan intentionally replaces the existing PDF test that accepts warning-only behavior. Warning-only PDF support is now treated as the root product gap, not as an acceptable fallback for PDF-only sources.

2026-05-27 subagent audit

Content pack image paths stay out of manifest.output_files until files exist. Planned image paths live in content-pack.json so the manifest does not claim outputs that were not generated.

2026-05-27 Task 2

Remote PDF extraction keeps the existing bounded download behavior, writes those bytes to a temporary file for the extractor seam, and hashes the bounded downloaded bytes rather than the temporary path.

2026-05-27 Task 3

PDF evidence now requires at least 200 Unicode letters after extraction and normalization. This filters scanned or very low-evidence PDFs into warning-only results instead of creating thin evidence items that look useful downstream.

2026-05-27 Task 5

Pipeline tests fake Poppler by putting a temporary pdftotext executable on PATH. This preserved the Task 5 file boundary and avoided exporting or editing the package-local PDF extractor seam in internal/source.

2026-05-27 Task 6

Pack planning uses planned target states by default and derives the overall pack status from target states. The hyphenated pack wire value handoff-ready and the underscored target wire value handoff_ready stay explicit in schema tests.

2026-05-27 Task 6 review

Unknown or empty target states now derive an overall partial status instead of planned. This avoids hiding malformed target state data when the pipeline starts writing pack artifacts.

2026-05-27 Task 7

Pack cleanup tracks only content-pack.json and the three generated brief.md files. It removes empty generated target directories after cleanup while preserving unrelated operator files under pack/.

2026-05-27 Task 5 review

After code-quality review, visualize doctor now reports only the first non-empty pdftotext -v line. This keeps doctor output readable without changing how Poppler availability is detected.

2026-05-27 Task 8

Quick mode keeps the single-image Codex handoff output visible, but when a content pack is active the printed POSIX command points at the pack prompt. This favors the multi-target workflow the user requested while preserving the older single-image prompt artifact.

2026-05-27 Task 9

Pack image generation is limited to explicit --backend openai in this slice. That keeps auto and hybrid fallback behavior unchanged while direct OpenAI runs gain multi-target generation and partial target failure handling.

2026-05-27 Task 10

--planner deterministic remains the default release-safe path. When --planner openai fails under --backend auto or --backend hybrid, the pipeline falls back to deterministic planning with a manifest warning; explicit --backend openai fails so remote-only runs do not silently become partly local.

2026-05-27 Task 10 review

The CLI reads the written content-pack.json before printing the planner line. This is intentionally a small local read instead of adding another manifest field, and it uses Go's os.OpenInRoot to keep the read scoped to the output bundle. Fallback runs now say deterministic when the actual pack was deterministic.

2026-05-27 Task 11

The public sample stays text-only rather than checking in PNG previews. This keeps the repository small and avoids presenting the local fallback PNG as a finished design output, while still showing the pack contract agents and renderers need.

Open Questions

2026-05-27 planning

Confirm after release slice 2 whether local/offline pack previews should remain briefs only, add a contact sheet, or render HTML screenshots. The approved spec allows previews only if they are labeled clearly as previews.

2026-05-27 subagent audit

Overall pack status uses the approved hyphenated wire value handoff-ready, while target state uses handoff_ready. If this feels awkward in practice, change it through a schema migration instead of silently changing the approved contract.
