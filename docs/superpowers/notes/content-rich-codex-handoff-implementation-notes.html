Content-Rich Codex Handoff Implementation Notes

Running notes for the content-rich packet, Codex handoff package, quick mode, manifest next steps, and scaffold upgrade work. Future implementation tasks should append to this file when behavior diverges from or interprets the spec.

Design Decisions

2026-05-26 planning

The first implementation plan treats --handoff codex --quick as the only supported quick-mode shape. Bare --quick should fail clearly instead of implying a handoff mode silently.

2026-05-26 planning

The plan starts with packet schema and dense markdown extraction before Codex prompt files. A polished handoff around a shallow packet would improve ergonomics but not output quality.

Task 1

Rich packet fields were added as optional JSON fields so existing v0.1 packet consumers continue to work while richer renderers can opt into structured content.

Task 2

Markdown section parsing treats fenced code blocks as opaque content so diagrams and code excerpts cannot accidentally create fake section headings.

Task 3

The packet builder now copies deterministic extraction output into packets before renderer work. Metric-backed claims are ranked before generic evidence claims so dense documents do not collapse into table-of-contents snippets.

Task 4

Scaffold HTML remains static and script-free, but now acts as an infographic outline for rich packet fields rather than only an audit list.

Task 5

Manifest next steps are treated as a required generated-bundle quality signal so agents are not left to infer what to do from backend metadata alone.

Task 6

Codex handoff files are deterministic local markdown files with private permissions. They include a remote-agent privacy warning and carry the rich packet fields into the image brief so the agent handoff does not require rereading original sources.

Task 6

Handoff output image paths are limited to bundle-relative paths, and existing symlinked handoff paths are rejected instead of followed. The handoff bundle should not instruct agents to write outside the generated output folder.

Task 6

Source-derived prose is flattened when inserted into prompt bullet lists, while diagrams use dynamic Markdown fences. This preserves diagram text without allowing source markdown to become handoff instructions.

Task 7

Quick mode prints a manual interactive Codex command and never runs Codex itself. This preserves the boundary between the Go CLI and Codex's agent-side image tools.

Task 8

Public docs present Codex handoff as a generated local package plus a manual quick command, not as a direct backend or automatic Codex execution.

Task 8

Sample regeneration exposed whitespace-only scaffold lines from omitted optional sections. The scaffold template now keeps standalone control actions unindented so generated excerpts stay diff-clean without trimming source-derived diagram text.

Deviations

2026-05-26 planning

Fallback PNG rendering is intentionally deferred from the first implementation pass. The spec marks it lower priority, and the plan focuses first on packet quality, scaffold usefulness, manifest guidance, and Codex handoff files.

Task 5

Manifest next steps do not mention --handoff codex until that flag exists. They point Codex users at scaffold.html and visual-packet.json to avoid generating a dead-end command in intermediate builds.

Tradeoffs

2026-05-26 planning

The plan uses deterministic local extraction rather than an LLM summarization stage. This keeps privacy and repeatability aligned with the existing release promise, at the cost of heuristic extraction instead of perfect semantic understanding.

Task 2

Markdown extraction is heuristic and deterministic. It preserves excerpts and simple structures instead of trying to perfectly understand every source document.
